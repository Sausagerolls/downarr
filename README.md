# Downarr

A native SwiftUI Mac app for running a home media stack: **Sonarr**, **Radarr**, **Jellyfin**,
**NZBGet** and **Deluge**. Server addresses and credentials are entered in Settings and stored in
UserDefaults; none are kept in the source.

## Running it

```sh
open build/Downarr.app       # already built and signed ad-hoc
./run.sh                     # rebuild + relaunch
./build.sh                   # rebuild only (Xcode), falls back to the CLT builder
./build-clt.sh [debug|release]  # build without Xcode at all
./make-icon.sh               # regenerate the app icon
```

> **Xcode licence note.** `xcodebuild` currently refuses to run on this Mac with
> *"You have not agreed to the Xcode license agreements"* (the installed Xcode's licence token is
> newer than the one that was accepted). Run this once to fix it:
>
> ```sh
> sudo xcodebuild -license accept
> ```
>
> Until then `./build.sh` automatically falls back to `./build-clt.sh`, which compiles with the
> Command Line Tools toolchain and assembles the `.app` bundle directly. Both produce the same app.
> `Downarr.xcodeproj` is generated by XcodeGen from `project.yml` (`xcodegen generate`) if you want
> to work in the IDE.

On first launch macOS asks *"Allow Downarr to find devices on local networks?"* — say **Allow**, or
nothing will load. (Already granted on this machine.)

## What's in it

**Dashboard** — health, version and reachability of all four services, library counters, disk use,
active downloads with progress, health warnings and stuck imports, the next 14 days of releases,
and what Jellyfin picked up most recently.

**Activity** — one table merging the Sonarr and Radarr queues with whichever download client is
actually moving the bytes: the NZBGet group (matched on release name) or the Deluge torrent
(matched on infohash, which is what the *arrs report as the download id). A blocked import shows
its download state in one place, and you can pause/resume/reprioritise in either client or
remove-and-blocklist in the *arr from the same row.

**Sonarr** — poster grid or sortable table over all 689 series, filters (monitored / missing /
complete), series detail with a fanart header, per-season accordions, per-episode monitor toggles,
file quality and size, automatic search per series/season/episode, **manual release search** with
rejection reasons and one-click grab, edit (profile, path, type, season folders), delete with or
without files, add-series flow over TheTVDB lookup, wanted list, history.

**Radarr** — the same surface for 492 movies: grid/table, detail with full media info, availability,
automatic and manual search, edit, delete, TMDB add flow, wanted, history.

**Jellyfin** (management, no playback) — library cards with paths and per-library scan/refresh,
server counters, scheduled-task triggers, and a browser over all 60k items with paging, type
filters, sorting and debounced search. Per item:

- **Metadata editor** — titles, sort title, overview, tagline, dates, ratings, parental rating,
  genres, studios, tags, locations, episode/season numbers, provider IDs, item lock and per-field
  locks.
- **Fix match** — search TheMovieDb/TheTVDB by name, year, episode number or provider ID, review
  results with posters, apply (optionally replacing artwork).
- **Images** — what's on the server with sizes, delete, upload a local file, and browse provider
  artwork filtered by type/provider/language with ratings and resolutions.
- Refresh metadata in any of the four modes, recursively for folders.

**NZBGet** — queue with per-item progress, category, priority, health and post-processing stage;
pause/resume/delete/move/priority/category per item or in bulk; global pause, speed-limit presets,
watch-folder scan, reload; history with decoded PAR/unpack failures, retry/mark-good/mark-bad; add
an NZB by URL.

**Deluge** — torrent list with progress, state, ratio, seeds/peers, tracker and label; filter by
state or label, sort eight ways, search. Per torrent or in bulk: pause/resume, queue top/up/down/
bottom, force recheck, per-torrent speed cap, relabel, remove with or without data. Server page
with transfer rates, free space, connections, DHT nodes, session paths, speed limits, label and
tracker breakdowns; global pause-all and download/upload limit presets. Add a magnet or `.torrent`
URL with label, location and add-paused.

**Calendar** — combined Sonarr + Radarr schedule grouped by day, 7/14/30 days or the last week.

`⌘1`–`⌘0` jump between sections, `⌘D` opens the torrent list, `⌘R` refreshes everything, `⌘,`
opens Settings.

## Icon

`Tools/IconGen/main.swift` draws the icon in CoreGraphics — a blue-to-violet rounded square with a
white download arrow dropping into a cyan tray — and renders each size in the `.iconset` from the
vector description instead of downscaling a single master, which keeps the 16pt and 32pt versions
sharp. To change it, edit the drawing code (colours live in `Palette`, geometry is expressed as
fractions of the canvas), then:

```sh
./make-icon.sh && ./build-clt.sh release
```

Both build paths set `CFBundleIconFile` to `AppIcon` and copy `Sources/Resources/AppIcon.icns` into
the bundle. macOS caches Dock icons aggressively; `touch build/Downarr.app` before relaunching if a
change doesn't show.

## How it's built

See `PLAN.md` for the design and the reasoning, `PROGRESS.md` for the build log, and
`docs/API-NOTES.md` for the exact endpoint shapes probed off the live servers.

Two decisions worth knowing:

- **Writes patch raw JSON.** Sonarr, Radarr and Jellyfin all replace the entire document on write.
  Downarr fetches the raw object, changes only the keys being edited, and sends it back, so fields
  it doesn't model can't be silently dropped.
- **Config lives in UserDefaults, not the Keychain.** The app is ad-hoc signed and rebuilt often,
  which invalidates Keychain ACLs; for a single-user local tool a plist is the pragmatic store.

## Verified against the live servers

Sonarr 4.0.19 · Radarr 6.3.0 · Jellyfin 12.0.0 · NZBGet 26.2 · Deluge 2.2.0: reads for every
screen, plus no-op write round-trips (`PUT /series/1` → 202, `PUT /movie/1` → 202,
`POST /Items/{id}` → 204) and a full image upload/delete cycle on a test item.

`./diagnose.sh` exercises every client against the live servers and prints the exact error for
anything that fails — much faster than driving the UI when something looks wrong.

Least-exercised path: applying provider artwork (`RemoteImages/Download`) — the endpoint is
correct, but it was not fired against live data to avoid changing real posters.
