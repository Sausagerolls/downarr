## What you need to prepare

### 1. Reviewer access (most likely rejection: Guideline 2.1)

The reviewer has no Sonarr/Radarr/Jellyfin/NZBGet/Deluge. If the app shows nothing but empty
settings, it gets rejected as "unable to review". Pick one:

- **Built-in demo mode (recommended).** A "Try demo" button on first launch that fills every
  screen with canned, non-copyrighted sample data. Most reliable; can be built in the app.
- **Public demo servers.** Instances reachable from the internet **over HTTPS** (ATS blocks plain
  HTTP to non-local hosts), with URLs and API keys in the App Review notes. They must stay up for
  the whole review, and every later update.

Either way, also attach a short screen recording of the app working with your real servers in the
review notes.

### 2. Piracy perception (Guideline 5.2.3 and 5.2.2)

Apple rejects apps that appear to facilitate illegal file sharing. Downarr controls a torrent
client, a Usenet downloader and release search, so presentation matters:

- Describe it as a remote control for **your own self-hosted media server**. Never mention
  torrents of films/TV, indexers, "free" content, or scene/release names.
- Screenshots: no real movie/TV posters or titles (copyrighted artwork in screenshots is itself a
  5.2 rejection) and no release names like the ones in the Deluge/NZBGet queues. Use demo data
  with public-domain or invented titles.
- Consider whether the Deluge section and interactive search should ship in v1.0. Removing them
  lowers the risk; similar Sonarr/Radarr clients are on the App Store, so keeping them is possible.
- Expect a reviewer question. Have a reply ready saying the app only talks to software the user
  runs, and that the app hosts and provides no content itself.

### 3. App Store Connect record

- Create the app: platform macOS, bundle ID `com.jakewatts.downarr` (Xcode registered the App ID
  while archiving), name, SKU, primary language.
- Check the name "Downarr" is available. If not, use something like "Downarr – Media Server Remote".
- Category: Utilities (already in the Info.plist) or Entertainment.
- **Privacy policy URL** (required). It can state that no data is collected and that settings and
  credentials stay on the Mac and go only to servers the user configures.
- **Support URL** (required). A simple page or a GitHub repo is fine.
- App Privacy questionnaire: "Data Not Collected". Data sent to the user's own servers is not
  collection by the developer.
- Age rating questionnaire. Posters and titles come from the user's library, so answer honestly
  (most similar apps use 4+ or 12+).
- Pricing and availability. A paid app needs the Paid Apps agreement, tax and banking set up.
- Screenshots at 16:10: 1280×800, 1440×900, 2560×1600 or 2880×1800, 1 to 10 of them.
- Description, subtitle (30 chars), keywords (100 chars), promotional text.

### 4. Quality items reviewers will notice

- First launch with no servers. The reviewer sees this before anything else, so make sure it
  explains what to do (or offers the demo).
- Screens still not verified on screen (see `PROGRESS.md`): series/movie detail, Jellyfin detail,
  metadata editor, identify, images, add series/movie, calendar, settings. A crash or broken
  sheet is an instant 2.1 rejection. Click through all of them in the sandboxed build.
- Test on macOS 14 (the minimum deployment target), not only macOS 27.
- Optional but recommended: move API keys and passwords from UserDefaults to the Keychain. The
  comment in `Config.swift` avoided Keychain only because builds were ad-hoc signed.

### 5. Each upload

1. Bump `CURRENT_PROJECT_VERSION` in `project.yml` (and `MARKETING_VERSION` for a new release).
2. `./archive.sh upload` (or `./archive.sh`, then drag `build/AppStore/Downarr.pkg` into
   Transporter).
3. Wait for processing, optionally test through TestFlight for Mac, then attach the build to the
   version and submit with the review notes.

## Testing the sandboxed build locally

App Store-signed builds do not launch outside the store. To test sandbox behaviour, build a
development-signed Debug copy:

```bash
xcodegen generate --quiet
xcodebuild -project Downarr.xcodeproj -scheme Downarr -configuration Debug \
  -derivedDataPath build/SandboxDD -allowProvisioningUpdates build
open build/SandboxDD/Build/Products/Debug/Downarr.app
```
